# Прототип 0.2 — доработки по пользовательскому тестированию

Дата: 25.10.2026. Версия приложения: 0.2.0. Основание — [семь замечаний и согласованные решения](user-feedback-requirements-0.2.md). Это обновление прототипа, а не приёмка полного MVP.

## Изменения

| Требование | Реализация |
|---|---|
| FB-01 | Нативный поиск регионов и населённых пунктов через Photon/OpenStreetMap. Подсказки в регистрации, выбор города в пределах региона, ID/источник/дата в профиле. Смена региона очищает зависимые выборы; отсутствие сети не уничтожает форму, доступен явно помеченный ручной ввод. |
| FB-02 | Русские названия событий, отдельные автор и цель с именем/ролью, часовой пояс компьютера, ID в подробностях. Новые события сохраняют зашифрованные подписи на момент действия, старые разрешают ID по текущей базе. |
| FB-03 | Имя и роль в открытом локальном списке, HMAC для проверки метаданных после разблокировки. Аутентификация использует account ID и авторитетную роль из БД. Одинаковые имена различаются суффиксом. Переименование обновляет список атомарно. |
| FB-04 | Алгебра, геометрия, физика, информатика для 7-го класса из единого каталога. Геометрия: три темы и девять задач с проверкой чисел/углов. Учебники по предметам независимы; карта знаний и история имеют фильтры. |
| FB-05 | Обязательный предмет ДЗ, необязательная совместимая тема. Нет fallback в math-equations; предмет передаётся в контекст модели. Для другой работы предлагается сохранить/приостановить занятие. Проверенный результат не меняет предмет при смене выбора. Повтор той же подтверждённой работы с тем же текстом/контекстом и версией подключения возвращает сохранённый результат без повторного запроса. |
| FB-06 | Редактор Python только для информатики. Нативный анализ проверяет владельца и предмет сохранённой работы; подмены UI-параметра недостаточно. Код не исполняется. |
| FB-07 | Переключатели четырёх предметов прямо над темами, клавиатурный доступ, явное выбранное состояние. Просмотр каталога не завершает занятие, черновики сохраняются. |

В ДЗ при отказе/отмене начального ИИ-запроса пустой активный сеанс не публикуется. Подтверждённый черновик остаётся доступен для повторной отправки. Согласия и лимиты продолжают проверяться в нативном слое.

## Источник адресов

Выбран Photon с данными OpenStreetMap. Это **не официальный ФИАС/ГАР**. Проверены реальные ответы «Самарская область → Самара»; полное покрытие всех российских населённых пунктов не утверждается. Публичный сервер допускает умеренное использование без гарантии доступности, поэтому есть native rate limit, debounce, cache и ручной fallback. На сервер уходят только адресный запрос/региональные ограничения, не регистрационная форма.

Документация источника: [Photon и условия публичного сервера](https://github.com/komoot/photon), [параметры API](https://github.com/komoot/photon/blob/master/docs/api-v1.md), [атрибуция OpenStreetMap](https://www.openstreetmap.org/copyright). В API используется `lang=default`: публичная инсталляция отклоняет `lang=ru`, а default возвращает локальные названия российских записей. Переход на официальный/иной адресный источник остаётся возможным через отдельный адаптер.

Школа по-прежнему вводится вручную. Таким образом, исправлен регионально-городской поиск из замечания №1, но школьная часть исходного AUTH-002 и автоматический поиск программы не объявляются готовыми.

## Обновление существующих данных

Схема 2 открывает контейнеры схемы 1. До миграции создаётся зашифрованный снимок `backups/before-migration-v1-<hash>.aead`; затем изменения публикуются атомарно. Повторное открытие не создаёт новые knowledge events и не начисляет освоение повторно. Сбой записи сохраняет исходный контейнер.

Старые занятия сохраняют исходный `subject=math`, программу и учебник на момент занятия. Для известных тем добавляется/вычисляется `catalog_subject=algebra`; неизвестные попадают в архивную группу. Старые общие назначения требуют нового предметного подтверждения, не копируются сразу в алгебру и геометрию. Старые строковые адреса остаются и помечаются неподтверждёнными.

На старой базе до первого успешного ввода пароля имена могут быть ещё недоступны: они извлекаются только после разрешённой расшифровки. После миграции список входа показывает имена и роли. Старые корректные ручные backup проверяются и мигрируют в staging до замены рабочей базы. Предыдущий формат приложения 0.1 не предназначен для работы с обновлённой схемой.

## Проверки и поставка

- 53 автоматических теста: предыдущие сценарии плюс адресный адаптер, проверки контекста/владельца, миграция, отказ записи, старый backup, публичные имена, аудит и повторы ДЗ.
- GUI-сценарий в реальном Qt WebView: регистрация через адресные подсказки, имена журнала/входа, переключение предметов, Python-панель, переход к ДЗ и тёмная тема. ИИ и адресный HTTP-транспорт этого теста синтетические.
- Отдельный live-тест адресного сервиса использует только публичные географические названия.
- Полный протокол, checksum и артефакты: [испытания 0.2](evidence/implementation-0.2.md).

Исполняемый файл выпускается отдельно как `dist/AI-Tutor-0.2.exe`, прежний exe не заменяется. Тесты выполняются на изолированных синтетических vault; пользовательская база разработчиком не мигрировалась.

Остаются ограничения полного MVP из [исходного статуса](implementation-status.md): OCR/vision, диктовка, полный годовой каталог, школьный справочник, калибровка педагогики, часть процедур управления ключами и вся окончательная приёмка на целевых ПК. Живые текстовые тесты четырёх ИИ-провайдеров этим обновлением не заменяются.
