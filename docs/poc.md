# План архитектурного прототипа — первые две недели

Статус: испытания не выполнялись. Цель — получить доказательства выбора стека и границ MVP, затем переоценить срок. Прототип не заменяет промышленную авторизацию, полную предметную базу и приёмку.

## Условия и артефакты

Нужны целевые Windows 10/11 x64, отдельная чистая среда без WebView2, второй совместимый ПК/VM для переноса, учётные данные четырёх провайдеров или Ollama с установленной моделью. Секреты не коммитятся. Наличие соответствующего оборудования, runtime, Rust/Node toolchain и API-ключей пока не проверено.

Перед установкой зависимостей выбрать актуальные версии по официальным источникам, проверить лицензии, зафиксировать lockfiles. Не выполнять тесты внешних сервисов с учебными данными реального ребёнка: использовать синтетический корпус.

Для каждого испытания сохранить в `docs/evidence/` протокол без секретов: дата, commit, Windows/runtime/toolchain, оборудование, шаги, ожидаемое/фактическое поведение, логи с redaction и checksum артефактов. Бинарные дампы с секретами и реальные профили в Git не добавлять.

## Предлагаемый порядок

Первая неделя: POC-01–05, начальные запросы POC-10. Если exe/пути/SQLCipher не проходят, сначала сравнить альтернативы и обновить архитектуру. Вторая: POC-06–14, итоговые ADR, риски и оценка оставшегося объёма. Ключи провайдеров и установленная локальная модель являются внешними предпосылками, их отсутствие фиксируется как блокировка соответствующей проверки.

## Решение по результатам

- Утвердить или заменить desktop-стек только после POC-01–04 и переноса.
- Утвердить схему ключей после POC-05–09; короткий PIN требует отдельного обоснования защиты от офлайн-перебора.
- Выбрать конкретные модели, распознавание и голос по POC-10/11/14, без приписывания всем моделям одинаковых возможностей.
- Уточнить минимальную конфигурацию ПК и численные NFR по замерам; не выбирать пороги задним числом без согласования.
- Пересчитать B01–B12 в рабочих днях с резервом на дефекты. При превышении 12 недель вынести изменение срока или состава на согласование; P0 автоматически не понижать.

Итоговый документ PoC должен различать `passed`, `failed` и `blocked`; этот план не содержит результатов испытаний.
