## Методика проверки exe

`tests/exe_qa_031.py` копирует exe в отдельные каталоги `build/exe031-…`, запускает с cwd `C:\Windows`, обслуживает тестовый Ollama-контракт на случайном loopback-порту и выполняет `tests/gui_qa_031.js` в реальном WebView. В отдельном запуске подготовленные пустое занятие и физическое наблюдение читаются именно скомпилированным нативным слоем; после завершения исходная запись сверяется.

Для тестового дочернего процесса включается локальный DevTools через переменную среды [по документации Qt](https://doc.qt.io/qt-6/qtwebengine-debugging.html). Это не изменение конфигурации приложения: обычный запуск и отдельный smoke выполняются без отладочного порта. В продукте не добавлены тестовые IPC-команды или автоматический доступ к данным.

## Миграция и ограничения

Новая SQL-миграция не потребовалась: схема остаётся 3, формат контейнера/backup не меняется. Классификация исправлена в DTO; исходные исторические наблюдения не требуют массового ремонта. Новые события сохраняют предмет и ID занятия; старые поля остаются необязательными при чтении. Проверены атомарный отказ записи и восстановление без подмены исходной базы.

Частичные проверки RQA-05/20 перечислены выше. Реальные облачные провайдеры, внешний Photon, второй ПК/чистая Windows, аппаратная производительность, полный корпус документов, инструментальный контраст и ранее не реализованные OCR/диктовка не проверены этим пакетом. Эти ограничения не скрываются за успешным smoke и не объявляются закрытыми.
