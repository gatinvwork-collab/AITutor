# Проверки Tutor-AI 0.6.0a1 — UF29

Дата: 29.10.2026. Это протокол разработчика, не независимый QA-отчёт. После его составления заказчик принял доработку 29.10.2026; результаты и ограничения проверок ниже сохранены. [Требования](user-feedback-requirements-2026-10-29.md), [решения](adr-0004-source-topic-jobs-trace.md), [обновление](release-0.6.0a1.md). Предыдущие QA-отчёты сохранены без переписывания.

## Версия и окружение

Windows x64, Python 3.13.15 из настроенного SDK проекта, PySide6/Qt WebEngine, зависимости `requirements-lock.txt`. PyCharm API окружения перестал отвечать в ходе работ; команды выполнялись последним подтверждённым интерпретатором `.venv/Scripts/python.exe`, без смены SDK и установки пакетов. Политика PowerShell не менялась; сборка выполнена прямым вызовом PyInstaller.

Финальный exe: `dist/Tutor-AI-0.6.0a1.exe`, 245106778 байт, SHA256 `98c8ae8384536510f1febb6eb957a0fd152a86d6953c6607e430cd615137c2b8`. SQL 5; AEAD и backup 1. [Манифест](evidence/feedback-0.6.0a1/manifest.json) связывает exe, снимок исходников и доказательства. Все базы испытаний синтетические, размещены отдельно в `build/`; рабочие `app-data` пользователя не использовались. Сетевые проверки — только loopback, без платных провайдеров.

Нативные новые тесты отдельно проверяют: будущие темы и решение родителя без фиктивного освоения; обход optional; банк больше 300 заданий через партии; пути ошибок JSON без содержимого ответов; совместимость по содержанию, а не году; единственный вызов финализатора; `failed` вместо ложного `stale`; reuse завершённого распознавания без нового запроса; отдельную отмену; opt-in, шифрование и маскирование trace; недоступность будущих эталонов ученику; отказ диагностики без изменения истории.

Первый полный запуск выявил два реальных дефекта до выпуска. Сегмент trace с длинным именем превышал ограничение обычных Windows-путей; исправлено поддерживаемым расширенным написанием после проверки границ каталога. Незавершённое задание при явном выходе неверно попадало в обработку аварии после нового входа; теперь выход фиксирует отмену, аварийный restart — прерывание. После исправлений полный набор прошёл. Ранние неуспешные результаты не считаются успешной приёмкой.

Исторические UI-драйверы адаптированы к согласованным маршрутам: редактирование программы проверяется родителем в «Программы и запросы», завершение попытки — в учебном процессе. Сначала старый драйвер искал убранную административную форму на ученическом экране и завершился ошибкой; после изменения только маршрута и роли он прошёл. Исходные независимые доказательства не изменены, проверки сохранности и черновиков сохранены.

## Ограничения приёмки

Физическая проверка исходников на одном окне Windows подтвердила фокус пароля, ввод и Enter без прокрутки, открытие списка и выбор предмета клавиатурой. Следующая сессия компьютерного управления была остановлена пользователем физическим Escape; повтор физического сценария на финальном exe не выполнен. DOM/CDP-тесты выше не подменяют эту проверку. Полная матрица DPI, размеров, первого клика, ошибок, тайм-аутов и отмен SEL29-A/B остаётся открытой.

Не выполнялись: запросы по двум исходным интернет-ссылкам пользователя; живое мультимодальное распознавание и оценка качества навыков; полный банк на выбранной облачной модели; положительный пример подходящего УМК 2023; полная матрица сбоев питания и заполнения диска. При жёстком завершении процесса внутри сетевой партии отдельные ещё не опубликованные ответы могут не попасть в постоянный журнал. После входа задание помечается прерванным и не запускается повторно автоматически.

Заказчик принял доработку 29.10.2026. Этот факт не заменяет отсутствующие испытания: закрытие всех обязательных сценариев UF29 и полнота MVP данным протоколом не подтверждены.
