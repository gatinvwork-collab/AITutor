# ADR-0001. Исполняемый прототип на Python / Qt WebEngine

Дата: 25.10.2026. Статус: применено для версии 0.1, окончательный стек пилотного MVP не утверждён.

## Контекст

Исходный Tauri/Rust/TypeScript/SQLCipher был предложением, требующим PoC. При проверке рабочего окружения обнаружены Python 3.13.15 и Node 24.19.0; Rust/MSVC не обнаружены в PATH и стандартных проверенных каталогах. Установка системного C++-набора не выполнялась. [Tauri требует соответствующие инструменты сборки Windows](https://v2.tauri.app/start/prerequisites/).

## Решение для 0.1

Использованы Python 3.13, PySide6 6.12.0 / Qt WebEngine, локальный HTML/CSS/JavaScript и QWebChannel. Нативная граница — `Service.dispatch` с allowlist команд и проверками роли/ресурса. Прямые HTTP-запросы, SQL и произвольные файловые пути WebView недоступны. Qt-профиль направлен в `app-data/cache` до создания страницы; это соответствует [порядку настройки QWebEngineProfile](https://doc.qt.io/qtforpython-6.8/PySide6/QtWebEngineCore/QWebEngineProfile.html).

Вместо SQLCipher используется SQLite `:memory:` с `temp_store=MEMORY`; целиком сериализованный снимок шифруется AES-256-GCM. [Сериализация SQLite возвращает образ базы](https://sqlite.org/c3ref/serialize.html); его открытая дисковая копия приложением не создаётся. Это отдельный формат хранения, а не SQLCipher-совместимый файл. Bootstrap и шифротекст лежат в одном атомарно заменяемом AEAD-контейнере. Обёртки ключа используют Argon2id (64 MiB, 3 прохода, 1 поток), случайные соли и AEAD с привязкой к vault/account/purpose. Пароль не используется напрямую как ключ данных. Короткий PIN запрещён до решения OPEN-03.

Оригиналы вложений отдельно защищаются AEAD с производным ключом и собственным ID в associated data; зашифрованные blobs находятся внутри БД. Поэтому backup автоматически включает оригиналы. Отдельный дисковый attachment store потребуется при росте объёма.

PyInstaller onefile содержит Python, Qt, Chromium и UI; при запуске извлекает системные временные файлы. Управляемые постоянные данные находятся у exe. WebView2 этой реализации не нужен. Один процесс-владелец vault обеспечивается QLockFile. Qt DLL и Chromium делают exe существенно крупнее предполагаемого Tauri-варианта.

## Подтверждено испытаниями

- Создание release exe на текущем Windows 11 x64.
- Автоматические проверки encryption/recovery/ACL/backup/идемпотентности и нативных лимитов; подробности в [статусе](implementation-status.md).
- Запуск реального Qt WebView и IPC-сценарий родитель → ученик → занятие → подсказка → тёмная тема.

## Ограничения и последствия

- Снимок целиком в RAM и полная перезапись при checkpoint подходят ограниченному прототипу, но требуют замеров на пилотных объёмах. Контейнер ограничен 256 MiB; импорт — 8 MiB. Дальнейший рост может потребовать SQLCipher и файлового хранилища.
- Python не гарантирует очистку всех копий immutable secrets из RAM. Подкачка, дампы ОС и доступ владельца ОС находятся за пределами гарантии шифрования дискового контейнера.
- Все локальные пользователи имеют обёртку одного ключа БД. ACL работают в приложении; владелец извлечённого ключа может читать всю БД вне него. Отзыв уже скопированных ключей и ротация ключа данных не реализованы.
- До входа показываются только непрозрачные идентификаторы. Имена находятся в зашифрованной БД.
- Полная нормализованная схема раздела 11 ТЗ ещё не реализована: `users`/`links` реляционные, остальные доменные агрегаты пока находятся в версионируемом record store.
- Совместимость с чистым Windows 10/другим ПК и количественные NFR ещё требуют испытаний. Версия 0.1 не является приёмкой MVP и не доказывает достаточность текущей криптосхемы для пилота.
- Перед распространением надо завершить проверку лицензий и комплект notices сторонних библиотек, особенно Qt/Chromium; текущая локальная сборка не является готовым публичным дистрибутивом.
