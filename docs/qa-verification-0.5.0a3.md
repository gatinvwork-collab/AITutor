## WebView и фактический exe

Новые формы: `tests/gui_qa_052.js`, source-harness `tests/gui_qa_052.py`, бинарный `tests/exe_qa_052.py`. **33 условия**: 9 сочетаний режима/уточнения, переключение select сразу после отправки, три последовательных разных режима с накоплением пар. На exe **12 фактически полученных loopback HTTP-запросов побайтно по содержимому messages совпали с журналом**. Все режимы проверены семантически. Платные/живые модели не использовались.

Бинарный fault-сценарий: `tests/exe_fault_052.py` — отдельная копия синтетической a2, Windows handle запрещает замену только её `vault.aead`, после проверки handle закрывается в `finally`. Реальный диск не заполняется, системные права и пользовательская база не меняются. **11 условий прошли**: после 186 секунд простоя при заблокированной записи попытка оставалась active с прежними секундами и daily, файл не изменился, уведомление было видно, ручная пауза не сообщала об успехе. После снятия блокировки следующий успешный tick установил paused и начислил **ровно 180 секунд**: попытка 0 → 180, daily 1.372725499997614 → 181.3727254999976. Следующие tick не добавили время, уведомление исчезло. Исходная a2 осталась неизменной. Grace и комбинированные отказы проверены нативно; отдельный бинарный grace-fault не выполнялся.

Прошли `tests/exe_qa_051.py` (прежние три ошибки, 30 условий предметов/черновиков, 8 условий обновления a1) и `tests/exe_learning_050.py` (30 общих условий учебного процесса, 5 UI + 10 нативных условий обновления 0.4.1). Исходные установки остались неизменными. Обычный запуск `--smoke` без DevTools из `C:\Windows`: exit 0, снимок получен, данные рядом с exe. Ruff и `node --check` прошли. Результаты и SHA256 каждого запуска находятся в отдельных JSON, без смешения логов процессов.

## Совместимость данных

Подлинная a2 получена из неизменённого `docs/evidence/qa-fix-0.5.0a2/frozen-source.zip`; версия исходника при генерации проверяется. Исходный exe a2: SHA256 `0ff0ecf7d3c2c9046bef522aebed07d653c0de55f93c89fb90c44ca7b9c965aa`. Созданная ею синтетическая база имеет 27 таблиц, семейные связи, recovery, PERS/согласия, утверждённый банк, ответы/оценки, активную после аварии попытку, оригинал PNG и журнал, в котором режим ещё не передавался модели.

Копии a2 и a1 прошли по **13 нативных условий**: хеши всех таблиц до первой записи, байты расшифрованных оригиналов, vault ID, схема, recovery, явное продолжение, старый предмет, новая неподтверждённая копия работы, продолжение диалога, неизменность прошлых payload, backup/restore и повторное открытие. Источники не модифицируются. Для 0.4.1 используется сохранённая синтетическая база схемы 3 и существующий verifier. Схема 4 и форматы контейнера/backup 1 не изменены.
