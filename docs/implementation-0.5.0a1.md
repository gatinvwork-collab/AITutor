# Tutor-AI 0.5.0a1 — предварительная реализация учебного процесса

Дата: 28.10.2026. Основание: [постановка A01–A20](learning-feedback-developer-specification-2026-10-28.md), [политика оценивания](learning-assessment-requirements-2026-10-28.md), [банк](learning-bank-requirements-2026-10-28.md). База: опубликованная 0.4.1, коммит `2ba1ca7`. **Это предварительная сборка, не завершение и не приёмка всего пакета A01–A20. Ограниченный банк не объявлен полным выпуском.**

## Изменения

- Схема 4 внутри прежнего AEAD-контейнера формата 1. Старые `users`, `links`, `records` и значения истории не переоцениваются. Предварительная зашифрованная копия проверяется до миграции; маршрут 1/2→3→4 публикуется одним checkpoint. Назначения, программы, рубрики, подборки, вопросы, компоненты, ответы, наблюдения, решения, операции, задачи и связи оригиналов имеют отдельные таблицы. SQL: [learning_schema.py](../tutor_ai/learning_schema.py).
- Сохранение реквизитов учебника отдельно от нормализации ИИ. Родитель меняет сразу, ученик предлагает изменение. Версии назначений сохраняются; опечатка не сбрасывает действующую программу. Новое издание явно сбрасывает текущую привязку; история остаётся.
- Ручной кандидат программы с обязательными навыками; отдельный предпросмотр и публикация родителем. Поиск по реквизитам, при отсутствии книги — поиск федерального ориентира; HTTPS-загрузка с проверкой публичного DNS каждого redirect и соединением с проверенным IP. ИИ разбирает источник во временной памяти. Нет автоматического признания источника официальной программой школы.
- Текущая тема и подтверждённое прохождение хранятся отдельно от знания. Временное исключение имеет конечный UTC, часовой пояс, решение/revision и отмену. В Windows проверка зоны использует Qt, не требует отдельной базы `tzdata`.
- Генерация вопросов, отдельный вызов содержательной ИИ-проверки, валидация структуры/навыков/повторов, затем конкретная подборка ожидает родителя. Эталоны не попадают в ученический DTO. Запасные вопросы той же утверждённой подборки можно использовать повторно без нового решения.
- Сохранённый план: тема 8+2*, предмет 27+3*, без повторения question ID в попытке. Для обязательных ошибочных тем скрининга требуется два физических вопроса; при невозможности соблюсти квоты — отказ. Подтверждение темы возможно только у `topic_confirmation`, при точном пороге 80%, полном покрытии рубрики, отсутствии U/S и самостоятельности.
- Ответ сохраняется до запуска ИИ. Исправление — новая версия, перепроверка/родительский вердикт привязаны к исходному ответу и компоненту. AI-only не становится C/W. Очередь ручной проверки и её решение отделены от допуска подборки. Неизвестный результат не заменяет вопрос в исходной попытке; API альтернативы создаёт новую попытку со ссылками на исходные вопрос/ответ/наблюдение.
- Пересчёт подтверждений, сигналов ошибок и успехов; три разных завершённых успешных попытки исключают точный вопрос для этого ребёнка из следующих планов. Повтор команды/перепроверки не увеличивает счётчик. Изменённый исходный вердикт пересчитывает производные данные.
- Работы с версиями текста, повторным добавлением зашифрованных оригиналов, предпросмотром изображения и явным подтверждением. GigaChat OCR требует нового `allow_images`, по умолчанию false. Временные удалённые файлы удаляются после операции; неподтверждённое удаление отображается отдельно. Проверка решения, подсказка и уточнение имеют разные намерения и один work ID; журнал сохраняет реальные учебные сообщения/ответы без транспортных секретов.
- Ограниченный формальный анализ арифметики и переходов линейных уравнений использует точные дроби и AST без исполнения. Его scope не объявляется проверкой всего решения/рубрики. Остальные решения доступны ИИ-анализу с ручным review; синтаксис Python не считается проверкой алгоритма.
- Локальный рендерер ограниченного Markdown/TeX→MathML с экранированием HTML, без внешних ресурсов. Неподдерживаемый TeX сохраняется читаемым исходником. Прежние тексты истории не переписываются.
- Отдельная ограниченная очередь сетевых задач: два исполнителя, до восьми принятых задач. Сеть не держит Service lock. Публикация проверяет vault/context, актёра, связь, разрешения и revision. Logout/restore/delete отменяют задачи; после перезапуска незавершённые задачи не отправляются повторно автоматически. Удаление ученика каскадирует новые персональные таблицы.

Нативная точка входа — разрешённая команда `learning` с закрытым набором `action`. Сессия и ACL определяются нативным Service; переданный student ID не предоставляет полномочий. Мутабельные команды используют operation ID, изменяемые сущности — revision. Повтор идентичной операции возвращает сохранённый результат, иной fingerprint отклоняется.

## Не завершено для полного пакета

| Задачи | Оставшаяся работа / граница предварительной версии |
|---|---|
| A01 | Полное оформление типизированного контракта и фиксация checksum миграции в БД. Сейчас действует закрытый набор действий/revision и внешний манифест исходников; это не полная реализация контрольных сумм миграций |
| A05 | Автоматический запуск точного поиска школьной программы после изменения школы, идентификация официального сайта и постоянный запрос ссылки при неуспехе. Сейчас поиск/импорт запускаются явно, ручной путь работает |
| A06 | Полноценное стабильное редактирование/сопоставление тем между версиями каталогов и интеграция нового каталога в экран «Предметы». Сейчас динамические темы и выбор текущей темы находятся в «Учебном процессе», «Предметы» сохраняют стартовый legacy-каталог. Новый кандидат создаёт новые topic ID; старые данные сохраняются, но автоматического переноса достижения на новую тему нет |
| A08/A17 | Генерация партиями и содержательная дедупликация эквивалентных задач; полный достаточный банк 8+2 по каждой теме и резерв по каждому конкретному изданию; принятая coverage matrix и положительный/отрицательный/неоднозначный корпус. Текущая проверка двух вопросов на навык не доказывает готовность всех точечных планов |
| A09 | Добор из отдельно подтверждённого прошлогоднего банка и полная оптимизация сложных комбинированных планов. Сейчас используется выбранная утверждённая подборка; при нехватке — явный отказ, прошлый курс не выдумывается |
| A10/A18 | Расширенный интерфейс апелляции и запуска альтернативы; API альтернативы есть. Причины технического сбоя пока видны прежде всего в задаче, не всегда как отдельная новая причина U компонента |
| A11 | Единый новый отчёт с архивными каталогами/фильтрами изданий и полная интеграция с существующими экранами карты/отчётов. Новая карта и попытки доступны в «Учебном процессе», прежние отчёты сохранены отдельно |
| A12/A13/A17 | Живой OCR печати/рукописи, подтверждённый пошаговый корпус всех выбранных тем и моделей, включая альтернативные методы. Transport-тесты с подменой сервера не являются такими испытаниями |
| A14 | Расширение контекста длительного диалога с сохранением лимитов; сейчас используется ограниченный контекст последних ответов. Полный локальный журнал не удаляется; при превышении 30 000 символов контекста требуется разделить работу |
| A15 | Полноценный визуальный редактор формул и расширенный Markdown/TeX. Сейчас textarea, локальный предпросмотр и безопасный fallback |
| A02/A16 | Расширенная аварийная матрица всех стадий миграции/atomic replace, ресурсов и близости к 256 МиБ. Реальная приёмка полного выпуска остаётся заблокирована непроверенными пунктами выше |

Это список фактически оставшейся работы, не согласованное сокращение требований. Нельзя заменять отсутствие поддержки темы бесконечным ручным fallback и объявлять полный пакет готовым. Для содержательной приёмки нужны конкретные программы/издания и модель; ключи и пароли не включаются в протоколы.

## Обновление и возврат

1. Для проверки используйте отдельную полную копию Portable-папки 0.4.1 с её `app-data`. Закройте старый процесс. Сначала проверьте работу на тестовой копии.
2. Новый exe кладётся рядом с копией `app-data`. Первый успешный unlock создаёт проверенный `backups/before-migration-v3-<hash>.aead` и переводит контейнер в схему 4; для 1/2 предусмотрен весь маршрут.
3. Пароли, recovery, vault/account IDs, derivation/AAD вложений и `.aitbackup` сохраняют прежний формат. Прежнее `allow_documents` не разрешает передачу фотографий; новое разрешение выдаётся отдельно родителем.
4. После аварийного завершения активные занятия/попытки требуют явного продолжения; время выключенного приложения не начисляется. Старые тесты продолжаются по прежнему обработчику, без добавления новых 30 вопросов.
5. Старый exe не открывает схему 4. Возврат — отдельно сохранённая полная папка 0.4.1. Обратная миграция и слияние новых записей в старую базу не реализованы. Резервная копия исходного контейнера не является обещанием автоматического downgrade.

Протокол и идентификация exe: [проверка 0.5.0a1](qa-verification-0.5.0a1.md). Реальные пользовательские базы в испытаниях не открывались.

Порядок действий в интерфейсе: [руководство предварительной версии](user-guide-0.5.0a1.md).
