# Повторное независимое тестирование Tutor-AI 0.5.0a2

Дата: 28.10.2026. **Исходные QA-050-01–03 исправлены в проверенных сценариях. Найдены два новых дефекта: QA-050-04 и QA-050-05.** Основной набор из 250 тестов прошёл, два дополнительных независимых теста ожидаемого поведения упали. [Реестр для программиста: приоритеты, воспроизведение, причины и критерии перепроверки](qa-bug-register-0.5.0a2-retest-2026-10-28.md).

## Объект и условия

Основания: текущий [README](../README.md), [выпуск a2](release-0.5.0a2.md), [требования исправлений](qa-remediation-requirements-0.5.0a1-2026-10-28.md), [реализованный объём и оставшаяся работа](implementation-0.5.0a1.md), руководства [нового](user-guide-0.5.0a1.md) и [прежнего](user-guide.md) интерфейса. Старые [протокол](qa-report-0.5.0a1-2026-10-28.md) и [реестр](qa-bug-register-0.5.0a1-2026-10-28.md) не переписывались.

Проверены текущие исходники **0.5.0a2, схема 4**, и готовый exe той же версии. Опубликованная 0.4.1 и предварительная a1 используются как источники синтетических данных для обновления. Полная повторная сертификация их отдельных старых exe не выполнялась.

Идентификация exe: 244 945 379 байт; SHA256 `0ff0ecf7d3c2c9046bef522aebed07d653c0de55f93c89fb90c44ca7b9c965aa`. Контрольные суммы текущих исходников сопоставлены с [манифестом a2](evidence/qa-fix-0.5.0a2/manifest.json); итоговая сверка записана в [summary.json](evidence/qa-retest-050a2-2026-10-28/summary.json). Рабочее дерево содержит незакоммиченные изменения разработки, поэтому версия установлена также по SHA256 файлов, а не только Git HEAD.

Среда: Windows 11, Python 3.13.15 из SDK проекта `.venv/Scripts/python.exe`, установленный Qt WebEngine и Node. Использован навык python-tools для выбора настроенного интерпретатора. Синтетические семьи создавались в новых папках `build/`; при нехватке места дополнительные небольшие испытания размещены в разрешённой рабочей папке Codex на C:. Рабочие базы заказчика не открывались. Production-код, существующие тесты, exe, ключи и настройки пользователя не менялись.

ИИ-провайдеры и адресные ответы подменялись тестовым транспортом; упакованный exe обращался только к локальному stub на loopback. Платные/живые модели и пользовательские credentials не использовались. Fault-проверка записи — временная подмена `store.save()` на синтетическом Service, а не преднамеренное заполнение диска.

## Методы, ресурсы и проверяемость

Полный прогон выполнен нативной командой:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests docs/evidence/qa-independent-050-2026-10-28/test_independent.py -q --basetemp=build/qa-retest-050a2-20261028 --junitxml=docs/evidence/qa-retest-050a2-2026-10-28/pytest.xml
```

Отдельно выполнен `test_additional.py` из нового каталога доказательств — оба нарушения подтверждены падением ожидаемого поведения. Прежние тесты/сценарии не редактировались QA. Новые файлы созданы только в каталоге доказательств и документации. Методы новых воспроизведений находятся в реестре.

Source GUI и exe запускались через терминал IDE: предыдущими испытаниями установлено, что sandbox-контекст не подходит для полноценного окна Qt. [Драйвер девяти GUI и двух exe-модулей](evidence/qa-retest-050a2-2026-10-28/run_suite.py) пишет отдельные логи, не совмещает результаты независимых процессов в один файл. Проверяются реальные Qt/WebView и bridge, формы отправляются программно; это не полный ручной прогон физической мышью и клавиатурой. Для file picker используются заранее заданные тестовые пути; импорт и нативные ограничения настоящие. Системная цветовая тема меняется средствами Qt-harness, не настройками пользователя Windows.

При старте на D: было 227 340 288 байт свободно. Основные тесты и GUI расходовали место на синтетические файлы/кэш; перед дополнительной копией для нативной проверки a1 осталось менее 40 МиБ, и защитный assert остановил только этот этап. Оба предшествовавших exe-модуля уже завершились с кодом 0. Общий `ide-exe.log` поэтому содержит отказ guard — его нельзя трактовать как полностью успешный первоначальный запуск. [Повторный драйвер](evidence/qa-retest-050a2-2026-10-28/verify_upgrade.py) разместил копию в разрешённой папке на C:, verifier завершился успешно. Там же размещён дополнительный exe-сценарий копирования работы. Источники, старые доказательства и данные ради освобождения места не удалялись. Нехватка места в окружении отделена от искусственного OSError в QA-050-04.

Сводка и копии JSON/снимков собираются [collect.py](evidence/qa-retest-050a2-2026-10-28/collect.py); проверяются SHA256 приложения и существование локальных ссылок отчётов. Контейнеры баз, expected.json с синтетическими recovery и секреты не копируются в каталог доказательств.

## Ограничения и заключение

Не выполнены живые запросы к OpenAI/GigaChat/Qwen/Ollama, проверка реальных сертификатов пользователя, педагогическая оценка всех тем/изданий, OCR печати/рукописи на настоящей модели, качество поиска школьной программы/реальная доступность адресного сервиса. Не аттестованы звук/русский голос Windows, физическая задержка изображения, полная матрица разрешений/аварий и предел near-256 МиБ. Capacity-нагрузка в этом прогоне не запускалась при малом свободном месте; обычный успех backup/restore её не заменяет. Fault QA-050-04 проверен на исходниках с инъекцией записи, а не на бинарнике при реальном отказе диска.

Незавершённые функции из статуса реализации сохраняют свой статус. Исходные минутные зависания пользователя и прежнее расхождение native-снимка с DOM этим автоматизированным прогоном не закрываются. Пройденная проверка фокуса не означает полного аудита доступности.

Рекомендуется передать программисту QA-050-04 (P1) и QA-050-05 (P2), затем повторить новые независимые тесты и затронутые GUI/exe-пути на пересобранном бинарнике с новым SHA256. Три прежних исходных воспроизведения устранены; выпуск в целом пока нельзя считать бездефектным или принятым в полном объёме A01–A20/MVP.
