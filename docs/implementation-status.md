# Реализация 0.1 и оставшийся объём MVP

Это исторический снимок версии 0.1. Актуальные изменения адресов, имён, предметов и ДЗ описаны в [релизе 0.2](release-0.2.md); перечисленные ниже ограничения оцениваются с учётом этого дополнения.

Дата: 25.10.2026. Это рабочий прототип, **не завершённый MVP 1.0**. Исходное ТЗ и его P0 остаются в силе. Выбор Python/Qt вместо предложенного Tauri описан в [ADR-0001](adr-0001-python-webview.md); разделы целевой архитектуры не следует читать как описание уже реализованных модулей.

## Реализовано в коде

| Область | Фактическое поведение |
|---|---|
| Desktop | Qt WebEngine, локальный UI, ограниченный QWebChannel, запрет внешних WebView-запросов, один экземпляр на vault, onefile-сборка |
| Portable | app-data у exe независимо от cwd; пути Qt cache/profile внутри него; ошибка записи без fallback |
| Данные | SQLite в RAM, полный AES-GCM-снимок на диске, Argon2id-обёртки случайного ключа; атомарная запись bootstrap и ciphertext |
| Профили | Ученик/родитель, ID, пароль от 10 символов; регистрация ребёнка родителем; первый родитель из профиля ученика |
| Семейные связи | Несколько детей, второй родитель через одноразовый 10-минутный код от связанного родителя; знание имени не даёт доступ |
| Права | Нативные проверки сессии/роли/связи; студент не получает секреты и чужую историю; revision-конфликты настроек |
| Восстановление | Recovery-ключ родителя, смена пароля без перешифрования истории, перевыпуск recovery, сброс пароля ребёнка |
| Провайдеры | HTTP-текст OpenAI/GigaChat/Qwen/Ollama; GigaChat OAuth/scope; список моделей; минимальные capabilities, usage и нормализованные ошибки; TLS-проверка |
| Разрешения | Отдельные gates для облачного текста и текста ДЗ/документов до HTTP; история изменения настроек с автором |
| Отмена | Пометка текущего запроса, отбрасывание отменённого результата; сетевое ожидание не всегда прекращается немедленно |
| Обучение | Объяснение ИИ + фиксированный банк практики для 7 тем; H1–H3; первая ошибка не открывает полное решение; пауза/продолжение/checkpoint |
| Диагностика | Тема/предмет; предварительное изменение уровня индекса банка по ответу; три наблюдения на тему, затем переход; без педагогической калибровки |
| Предметные проверки | Ограниченная арифметика с дробями без eval; эталонные ответы банка; обязательные единицы в поддерживаемых физических задачах; Python AST без исполнения |
| ДЗ | Текст, импорт TXT/PY/CSV/PDF/DOCX/изображений; зашифрованный оригинал; подтверждение текста; ИИ-подсказка помечена как непроверенная |
| Знания | Попытки, успехи, подсказки, ошибки, mastery/confidence/trend, даты практики/повторения; меньший вес ответов с подсказками; идемпотентность |
| Родителю | Связанные дети, история и недельный/месячный срез, карта знаний, показатели времени, лимиты, согласования учебника |
| Время | Монотонный таймер, checkpoints, дневной лимит, до 15 минут сверх лимита, idle-пауза; ДЗ не обходит лимит |
| Backup | Ручной архив с отдельным паролем, ежедневный auto после входа родителя, проверка копии/пароля родителя перед заменой, сохранение зашифрованного предыдущего состояния |
| Темы | Светлая/тёмная/системная, настройка по профилю; CSS реагирует на системную тему |
| Аудио | Системное TTS через Qt при наличии голоса; текст доступен при его отказе |

## Не реализовано или требует существенного продолжения

- AUTH-002/EDU-001–004: классификатор регионов/городов/школ, автодополнение и поиск официальной программы с доказательствами источника. В 0.1 поля и учебник вводятся вручную.
- AUTH-003: полноценное редактирование регистрационного профиля; независимая самостоятельная регистрация в уже существующем заблокированном vault пока недоступна.
- SEC/OPEN-03/04: безопасная PIN-схема, ротация ключа данных, отзыв извлечённых ключей, независимый разбор криптосхемы. Очистка копий секретов из памяти Python не гарантируется.
- DB: полная реляционная схема и миграции между релизами; сейчас схема v1 с record store для агрегатов. Политика независимых семей/vault ещё не реализована.
- EDU/TUT: полный проверенный каталог 7-го класса, зависимости тем, программа по предметам, полное покрытие учебниками, все педагогические состояния/стратегии H0–H5 и калибровка диагностики/знаний. Текущий банк мал и не покрывает учебный год.
- HW/VOICE: автоматическое OCR рукописи/фото/формул, visual-анализ рисунков/графиков, диктовка STT и её редактор. Изображения пока требуют ручной расшифровки.
- UI-007: специализированный renderer формул и графиков, полнота всех 20 экранов (часть функций объединена, часть отсутствует); независимые настройки STT/TTS.
- AI: проверенные per-model capabilities, мультимодальность и streaming. Эти функции возвращают unsupported, а не приписываются всем моделям.
- BKP: восстановление в пустую установку через UI, восстановление по recovery непосредственно из backup, настройка отключения дополнительного шифрования и полноценная политика retention. Auto-архив использует ключ текущего vault и не заменяет переносимую ручную копию с отдельным паролем.
- Удаление: сервис удаляет ученика только при единственном связанном родителе; полный UI, процедура нескольких родителей, удаление родителя/связей и работа со старыми backup ещё не готовы.
- NFR: минимальный целевой ПК и пороги производительности, нагрузочные испытания, Windows 10/чистый ПК/перенос на второй ПК, аварийные отключения питания и независимый security review.
- Пилот: лицензии/права на материалы и комплект сторонних notices, решения по данным детей, полный приёмочный корпус и педагогическая оценка.

## Проверки

Автоматические тесты находятся в `tests/test_application.py`; контракты HTTP проверяются через `httpx.MockTransport`. Испытания с реальными API-ключами **не выполнялись**. Ключи не запрашивались и не подменялись тестовыми ответами в приложении.

GUI-тест `tests/gui_smoke.py` запускает реальный Qt WebView и нативный bridge с синтетическими профилями; только провайдер заменён FakeProvider. Он проверяет создание родителя/ребёнка, отображение кабинета, вход ученика, старт темы, ошибочный ответ, подсказку и тёмную тему. Артефакты появляются в `build/gui-<id>/`; там нет реальных учебных данных.

Запуск unit/integration-тестов и проверки GUI не означает прохождение всех AT-01–AT-38. Финальный протокол и checksum локального exe сохраняются в `docs/evidence/implementation-0.1.md` после завершения сборки.

## Очередность следующей реализации

Сначала закрыть ключевые решения безопасности и нормализацию/миграции хранилища; затем школьный каталог, OCR/vision и STT; параллельно расширять и педагогически проверять учебный банк. После этого — матрица моделей и живые тесты четырёх провайдеров, аварийное восстановление и испытания Portable на целевых ПК. P0 не считается готовым только по наличию экрана или тестового адаптера.
