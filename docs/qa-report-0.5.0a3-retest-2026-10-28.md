## Перепроверка исправлений

**QA-050-04.** Нативные проверки охватывают обычный tick, idle, остаток grace 5 секунд и сочетание idle/grace при трёх последовательных отказах save. При отказе SQL, файл, runtime и временные отметки сохраняются, повтор не дублирует начисление. На exe удерживался Windows handle без FILE_SHARE_DELETE только к vault отдельной тестовой копии. После 186 секунд реального простоя попытка оставалась сохранённой active, время/daily не публиковались, предупреждение было видно, неуспешная ручная pause не сообщала об успехе. После освобождения handle попытка стала paused, время 0 → 180, daily 1,3727255 → 181,3727255; предупреждение исчезло. Последующие ticks не добавили время. Hash отдельного источника a2 не изменился. Это испытание управляемого запрета замены файла, а не физического отказа накопителя/питания.

**QA-050-05.** Проверены check/hint/follow_up × пустое/пробельное/непустое уточнение, изменение select сразу после отправки, три последовательных разных режима в одной работе. Проверяется конкретная инструкция в фактическом system message; текст вопроса дополняет режим. Для exe сравнивались также 12 реальных loopback HTTP-запросов с локальным журналом, а не только различие метаданных. Старые payload не переписываются; режим прошлого вызова отмечается отдельно и не выдаётся за текущий.

**QA-050-01–03.** Четыре старых независимых проверки входят в полный прогон; exe-сценарий отдельно проверяет продолжение B после завершения A, предыдущую пару диалога и requested=selected=created. Дополнительно проверены четыре предмета, Python только по правильному предмету, черновики, их сброс/очистка, поздний overview и неизвестный subject. Новая ошибка активности не отменяет эти положительные результаты: она возникает при нескольких принятых запросах одной работы на временном интервале больше трёх минут.

## Новый контрпример QA-050-06

На исходниках FakeProvider успешно отвечает при монотонных clock 100, 160 и 220. `last_action` остаётся 100. Четвёртый запрос при 281 получает `time_limit`; занятие paused, учтено 180 секунд. Между последними успешными учебными действиями прошло менее 180 секунд, поэтому это ложное бездействие.

На готовом exe выполнены настоящие формы в той же работе, без подмены часов продукта. Уточнения успешно завершились примерно на 0,375 / 60,515 / 121,083 с. При наблюдении на 191,257 с занятие paused, seconds=180, хотя после последнего успеха прошло только 70,174 с. [Нативный тест](evidence/qa-retest-050a3-2026-10-28/test_additional.py) и [сценарий exe](evidence/qa-retest-050a3-2026-10-28/compiled_dialogue_idle.js) хранят разные методы воспроизведения одного дефекта. Подробности и рекомендации — в реестре.

## Методика и артефакты

Основной прогон выполнен нативно настроенным интерпретатором:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m pytest tests docs/evidence/qa-independent-050-2026-10-28/test_independent.py docs/evidence/qa-retest-050a2-2026-10-28/test_additional.py -q --basetemp=build/qa-retest-050a3-20261028 --junitxml=docs/evidence/qa-retest-050a3-2026-10-28/pytest.xml
```

Новый `test_additional.py` запускался отдельно с новым basetemp и дал одно падение. Для повторных запусков выбирать новый суффикс basetemp: pytest очищает заданную папку.

Qt GUI/готовый exe выполнялись через терминал IDE, поскольку ранее установленное ограничение sandbox не позволяет надёжно проводить оконные сценарии в нём. [Драйвер](evidence/qa-retest-050a3-2026-10-28/run_suite.py) запускает модули с отдельными логами. Использованы настоящие Qt/WebView, нативный bridge, программные отправки форм и локальный CDP. Это не полная ручная проверка физической мыши/клавиатуры. Для file picker указаны тестовые результаты, дальнейший импорт настоящий. Оформление системной темы проверялось через Qt-harness без изменения пользовательских настроек Windows.

В fault-тесте handle закрывается в finally; блокируется только собственный тестовый vault. Живые ИИ/платные запросы не выполнялись: native использует FakeProvider/MockTransport, exe — loopback stub. В новом сценарии диалога используются реальные задержки 60/60/70 секунд и штатный фоновый tick, без продуктовых переключателей неисправности или подмены clock.

Перед началом было около 1,61 ГБ свободного места на D:. Результат не требовал удаления старых данных или доказательств. Синтетические базы, recovery и expected.json остаются в тестовых папках; в каталог доказательств копируются только результаты, сценарии и снимки. [Сборщик](evidence/qa-retest-050a3-2026-10-28/collect.py) сверяет хеши приложения и проверяет локальные ссылки отчётов.

## Ограничения и решение о готовности

Живые OpenAI/GigaChat/Qwen/Ollama, реальные сертификаты, OCR печати/рукописи и педагогическое качество всех тем/изданий не аттестованы. Не проверены заново реальная доступность адресного источника, качество поиска программ, аудиовывод и русский голос Windows, аппаратный сон/пробуждение, физическая задержка окна и исходные минутные зависания пользователя. Отдельный бинарный grace-fault, физический отказ диска/питания, полная аварийная/аппаратная матрица и near-256 МиБ не выполнялись. Положительный управляемый idle-fault их не заменяет.

Незавершённые A01–A20 из статуса реализации остаются незавершёнными; успешная регрессия не превращает предварительную версию в принятый MVP. Результат: исходные QA-050-01–05 устранены в проверенных сценариях, **QA-050-06 открыт**. Для следующего исправления требуется успешный новый независимый тест, реальные интервалы на пересобранном exe с новым SHA256 и сохранение прежней регрессии.
