# ADR-0003. Оформление, анкеты и уведомления

Дата: 26.10.2026. Статус: реализовано в прототипе 0.3. Основание: [требования](user-feedback-requirements-0.3.md).

`users.theme` сохраняет прежний смысл цветового режима. Новое поле `design` (`strict/modern`) независимо от роли после первоначального назначения; `profile_revision` защищает анкету от устаревшего сохранения. Системное оформление передаётся из Qt `QStyleHints.colorSchemeChanged` в WebView как несекретное состояние; CSS media query остаётся запасным вариантом.

Команды `get_profile` и `save_profile` используют отдельную проверку доступа: сам пользователь, связанный ребёнок либо другой родитель с общим подтверждённым ребёнком. Эта проверка не используется для выдачи учебных данных другого семейного круга. Список редактируемых анкет не возвращает учётные данные. Отдельные операции паролей/ключей не получают новых полномочий.

При адресном изменении учеником в той же транзакции создаётся запись `notification` для каждого родителя. Запись содержит ID события, получателя, ученика, автора, дату, изменения и `read_at`; владелец записи — ученик, поэтому существующая процедура удаления его данных удаляет уведомления. Выдача и прочтение требуют актуальной связи и совпадения получателя. В открытый список входа уведомления и школьные данные не попадают.

Архивы вычисляются в безопасном снимке по доступным данным ученика и типу экрана. История не удаляется для исправления фильтра. Миграции 1/2 → 3 выполняются в памяти с зашифрованным снимком и единым атомарным сохранением; никаких новых семейных связей миграция не создаёт.
