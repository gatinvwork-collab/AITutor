# Учебный процесс: требования по результатам тестирования

Дата исходного пакета: 27.10.2026. Дополнено 28.10.2026. База: Tutor-AI 0.4.1 по README на момент исходного анализа; фактическую исходную сборку фиксировать перед обновлением. Статус: **правила диагностики уточнены; декомпозиция возможна, Q7 и Q8 согласованы; полный генерируемый банк готов к технической декомпозиции**. Актуальная строгая модель — [EVAL/UNK от 28.10](learning-assessment-requirements-2026-10-28.md). Выполнен статический анализ исходников и последующее документальное уточнение, без изменения программы, сетевых запросов, запуска тестов и реальных пользовательских данных. Номер будущего релиза не назначен.

### Решения заказчика по итогам уточнений

1. Задачи повышенной сложности необязательны: помечаются «*», их можно пропустить.
2. Диагностика предмета всегда содержит 30 вопросов: 27 обязательных и 3 со «*». Для проверки темы планируется минимум 2 разных вопроса; одно задание может действительно проверять несколько тем, например 2–3. Темы, которые не удалось включить с достаточным покрытием, нового подтверждения не получают. При недостатке тем набор дополняется темами прошлого учебного года. Это заменяет прежнее правило 10 вопросов при 1–2 темах и порог «3 пройденных темы».
3. Запрет повторов относится к одной попытке. Запрет повторного использования вопросов в новой попытке не запрошен.
4. Родитель исправляет учебник сразу, ученик — через подтверждение родителем. Поиск учебника и его тем производится по реквизитам.
5. Подтверждены прямая проверка готового ДЗ без обязательной подсказки, уточнения в диалоге той же работы и последовательность «фото → OCR → редактирование → подтверждение → проверка».
6. В приоритете темы с проблемами по последним тестированиям/ДЗ и темы без оценки, для которых подтверждено прохождение материала. Новое подтверждение темы отделяется от прежней оценки и от факта прохождения материала.
7. Уточнение 28.10: предметная диагностика — скрининг проблемных тем, без выдачи подтверждения. Подтверждение возможно только по точечной диагностике полного обязательного минимума темы; любой U или непроверенный обязательный элемент его запрещает. Два правильных вопроса сами по себе достаточным доказательством не являются. Непроверенные результаты имеют причины; неприем отправки ответом не считается.
8. Итог Q7: порог подтверждения 80% по первому самостоятельному ответу при полном проверенном покрытии; ручная проверка/апелляция — связанный родитель. Темы с доказанными ошибками обязательно включаются в общую диагностику, даже при достигнутом пороге. Подробности — EVAL-03/06/09/10 связанного дополнения; это сильнее прежнего общего приоритета проблемных тем.
9. Итог ответов Q8: ограниченный BANK-1 заменён [полным генерируемым банком](learning-bank-requirements-2026-10-28.md) по программе/учебнику с федеральным fallback, ИИ-предметной проверкой, утверждением состава родителем и автоматическим допуском. Обязательны шаги решения, фото при каждом уточнении, журнал ИИ-запросов/ответов и персональная замена вопроса после трёх успешных разных тестов. Запрет хранения полных учебников не отменяет автоматически историю; границы хранения и проверки согласованы: метаданные/история сохраняются, ИИ-only требует решения родителя, каждая новая подборка утверждается родителем.

## 2. Сопоставление с текущей реализацией

| Область | Подтверждённое чтением исходников состояние | Разрыв |
|---|---|---|
| Вопросы диагностики | В `education.py` по три фиксированных задания на тему. В `Service.answer()` next_index ограничен 0–2, смещается по правильности ответа; завершение после трёх засчитанных ответов на тему | Возврат к показанному заданию возможен; нет требуемых квот и устойчивого плана уникальных вопросов |
| Область диагностики предмета | `topic_queue` строится по всему статическому каталогу предмета | Нет привязки к конкретному учебнику и явному статусу «пройдено» |
| Учебники | `request_program()` доступен ученику; родитель принимает/отклоняет запрос. UI родителя не содержит формы исправления назначенного учебника; существующая форма ученика не является редактированием с заполненными значениями | Нужны операции редактирования, версии и согласованный порядок утверждения |
| Нормализация и темы | Ручные поля title/authors/publisher; фиксированный каталог `education.py` | Нет ИИ-нормализации и извлечения оглавления конкретного издания |
| Школа и программа | `save_profile()` сохраняет школу и уведомляет родителей. `addresses.py` ищет регионы/города. UI явно пишет, что автоматический поиск программы не подключён | Адресный поиск не является поиском программы школы; нет процесса поиска/источников/запроса ссылки |
| Карта знаний | `knowledge()` показывает только существующие knowledge-записи | Изучение не начавшейся темы не отображается; нет периода исключения и родительского решения |
| Фото | `documents.py` проверяет изображение, но выдаёт статус manual и требует переписать текст | OCR не реализован; нужен редактируемый результат с формулами |
| Проверка ДЗ | `check_homework()` просит ИИ найти первый ошибочный шаг или уточнить; UI предлагает только «Получить наводящую подсказку» | Нет самостоятельного режима проверки готовой работы |
| Продолжение ДЗ | `lessonPage()` для homework не содержит формы продолжения; результат ДЗ выведен в pre | Вопрос ИИ не имеет доступного поля для ответа; диалог обрывается |
| Независимая проверка | ДЗ сохраняется с verified=False, но UI безусловно пишет «ответ ИИ не прошёл независимую предметную проверку». `check_answer()` сравнивает ограниченные выражения для каталожных заданий, не является анализатором многострочного решения | «Не проверено» ошибочно звучит как отрицательный результат; нужен честный предметный статус |
| Отображение | Тексты экранируются через esc и выводятся как текст/pre; в изученном HTML нет Markdown/TeX-рендерера | Безопасный текстовый вывод сохраняет сырую разметку и формулы |

Статические наблюдения не подменяют воспроизведение на exe. Сообщение заказчика о работоспособности GigaChat принято в связанном отчёте; оно не подтверждает отдельно OCR, правильность математического анализа или полноту новой диагностики.

## 3. Учебники: редактирование и единое наименование

| ID | Требование | Критерий приёмки |
|---|---|---|
| BOOK-01 | Редактировать выбранный учебник с предзаполненной формой | Можно исправить реквизиты и источник, увидеть изменения и сохранить без потери исходных данных. Согласованная матрица: родитель связанного ребёнка изменяет сразу; ученик создаёт предложение на подтверждение родителю. Пока предложение ожидает решения, действует прежняя версия |
| BOOK-02 | Разделить исправление реквизитов и замену учебника/издания | Исправление опечатки не удаляет темы/историю; замена издания создаёт новую версию назначения и требует проверки соответствия тем. Исторические занятия сохраняют прежний снимок |
| BOOK-03 | Контролировать права и конфликты | Автор, время, исходная revision и решение записаны; устаревшее изменение отклоняется с предложением перечитать; родитель не меняет учебники чужого ученика; отмена не публикует черновик |
| BOOK-04 | При добавлении и существенной правке предложить нормализованное имя через ИИ | Предлагаемый шаблон: «Предмет. Класс — Название / Авторы. — Издательство, Год. — Часть, издание». Последние поля опускаются, если неизвестны; ИИ не выдумывает ISBN, год, авторов и издательство. Шаблон — предложение аналитика, не требование заполнять все поля |
| BOOK-05 | Сохранение/отправка предложения не зависит от ответа ИИ | При отсутствии подключения, отказе согласия, timeout или ошибке сохраняются исходные поля и первоначальное имя. Нормализация — фоновая подсказка с состоянием; ошибка не отменяет успешное сохранение. Запоздалый ответ не перезаписывает новую правку |
| BOOK-06 | Сохранять происхождение нормализации | Отдельно исходное имя, структурированные поля, предложенное имя, статус и версия. Изменения фактов/издания требуют подтверждения; исходный ввод всегда доступен; история не переименовывается задним числом |

ИИ получает только необходимые реквизиты учебника с действующими разрешениями, без ФИО/школы/семейной истории. Повтор нормализации после восстановления подключения — явное действие либо видимая задача; не создавать незаметный бесконечный повтор.

## 4. Учебник, программа, темы и текущая тема

Учебник, школьная программа и текущая тема — разные сущности. Книга задаёт оглавление; программа — план для класса/года; текущая тема — состояние конкретного ученика. ИИ не заменяет отсутствие документального источника правдоподобным ответом.

| ID | Требование | Критерий приёмки |
|---|---|---|
| CUR-01 | Находить учебник по реквизитам и получать полный перечень его тем | Основной путь — поиск по названию, авторам, предмету, классу, издательству и известным году/части/изданию. Не требовать ссылку/файл от пользователя для начала поиска. Из найденного источника извлекается оглавление именно выбранного издания; неоднозначные совпадения показываются для выбора. Сохранены предмет, класс, издание, проверяемый источник, дата, порядок, главы/параграфы и версия каталога. Ответ ИИ без источника не объявляется достоверным оглавлением |
| CUR-02 | Подтверждать импорт и показывать неполноту | Предпросмотр позволяет исправить пропуски/дубли. Неполное оглавление не объявляется полным. При отсутствии доступного источника запросить ссылку/файл/оглавление; ручной ввод доступен, сохранение учебника не блокируется |
| CUR-03 | Дать темам стабильную идентичность | ID отделён от названия и номера в оглавлении. Переименование не обнуляет знания; совпадающие названия разных книг не объединяются автоматически. После замены книги предложить явное сопоставление тем, неподтверждённые остаются отдельными/архивными |
| CUR-04 | Запрашивать текущую тему при выборе предмета в «Предметах» и «Проверке ДЗ» | Показать список тем назначенного учебника и класса, ранее выбранное значение и возможность «Не знаю / ещё не изучали». Переходы не теряют черновик; выбор синхронизирован для данного ученика/предмета, но тема конкретной работы фиксируется отдельно |
| CUR-05 | Не приравнивать текущую тему к освоению | Выбор ученика не начисляет правильные ответы и не делает все предыдущие темы освоенными. Источник и время выбора сохраняются; смена текущей темы не переписывает старые работы |
| CUR-06 | После сохранения/выбора школы запускать поиск учебной программы для класса и учебного года | Явные состояния: не начат, поиск, кандидат, подтверждено, не найдено, ошибка. Сначала идентифицировать школу/официальный сайт; не смешивать одноимённые школы. Школа сохраняется независимо от поиска |
| CUR-07 | Использовать ИИ для разбора найденных источников, а не как выдуманный источник | Кандидат содержит URL документа/страницы, год, класс, предмет, дату и степень уверенности. Наличие ИИ само по себе не даёт доступа к интернету; нужен отдельный загрузчик/поиск. Предоставленные страницы и документы считаются недоверенными данными |
| CUR-08 | Если программа не найдена, запросить ссылку у родителя | Постоянное уведомление и поле ссылки доступны связанному родителю. «Сеть недоступна» отличается от «источник не найден». Есть повтор и ручной путь; ученик продолжает работу с текущей подтверждённой программой |
| CUR-09 | Проверять родительскую ссылку и применять программу через подтверждение | Показывать статус загрузки/извлечения и предпросмотр. Не запрашивать пароль от школьного сайта; ограничить протоколы, размер, время загрузки и перенаправления; не допускать чтение локальных/внутренних ресурсов через URL. Смена школы делает старого кандидата неактуальным, но не удаляет историю |

Полный текст учебника не загружается из случайного источника только по совпавшему названию. Программа/оглавление без источника имеют явный неподтверждённый статус. Обновление справочника не меняет уже сформированную диагностическую попытку.

## 5. Диагностика и отсутствие повторов

| ID | Требование | Критерий приёмки |
|---|---|---|
| DGN-01 | Формировать и сохранять план конкретной попытки | До выдачи определены темы, квоты, уровень, стабильные question_id и версия содержания. План переживает паузу/перезапуск; восстановление не генерирует новый вопрос вместо текущего |
| DGN-02 | Исключить дубли внутри попытки | Один вопрос не засчитывается как несколько разных; учитывать ID, нормализованное условие и эквивалентные переформулировки. Небольшая смена текста того же задания не считается новым заданием |
| DGN-03 | Различать новый вопрос, повторную попытку ответа и повтор операции | Повторная отправка сети идемпотентна; исправление ответа не увеличивает число уникальных вопросов. Повтор после ошибки явно помечен и не заполняет квоту новым вопросом |
| DGN-04 | Исключить дубли внутри попытки и ротировать усвоенные вопросы | До трёх успешных разных тестов вопрос может повториться в новой попытке; после третьего для этого ученика помечается усвоенным и заменяется новым аналогом по теме согласно ROT-01–05. Один тест с тремя отправками не считается тремя тестами. Продолжение после паузы/перезапуска остаётся той же попыткой; историю и начатый план не менять |
| DGN-05 | Проверять достаточность банка и качество сгенерированных заданий | Нет запуска короткой диагностики под видом полной; при нехватке вопросов подготовить/дополнить банк или сообщить о нехватке. ИИ-вопрос содержит тему, уровень, ожидаемый результат и способ проверки; не проверяется только словесным согласием той же модели |
| DGN-06 | Диагностика темы содержит минимум 10 уникальных вопросов | Базовый набор: 8 обязательных и 2 повышенной сложности. Сложные обозначены «*» и имеют действие «Пропустить». Пропуск не считается ошибкой и не снижает результат обязательной части; базовое и повышенное освоение отражаются отдельно |
| DGN-07 | Диагностика предмета всегда содержит 27 обязательных + 3 со «*» | Всего 30 уникальных заданий независимо от числа тем. Одно задание может проверять несколько тем; для достаточного покрытия отдельной темы требуется минимум 2 разных задания. При невозможности включить тему с достаточным покрытием она не получает нового подтверждения. При недостатке тем набор дополняется темами прошлого года; квоты неизменны. Прежние пороги 1–2 / 3+ пройденных тем отменены |
| DGN-08 | Не подменять полноту теста числом верных ответов | Ошибочный ответ засчитывает пройденный вопрос, но не правильный; неопределённость проверки — отдельный статус. Завершение возможно после ответа на обязательные вопросы и ответа/явного пропуска каждого «*»; пропуск сложных не делает диагностику незавершённой. Пауза, лимит времени или ручное завершение до обработки обязательной части дают незавершённую попытку. Итоги разделяют запланированное и фактическое покрытие, обязательные/сложные, решённые/ошибочные/пропущенные/непроверенные |
| DGN-09 | Сохранить адаптацию, не нарушая квоты и покрытие | Сложность может адаптироваться в пределах плана; нельзя циклически вернуться к трём заданиям и завершить раньше квоты. Подсказки и самостоятельность сохраняются отдельно; не менять старые результаты по новым правилам |
| DGN-10 | Поддержать содержательно комбинированные задания | Один question_id содержит несколько проверяемых тем, например 2–3, с отдельным ожидаемым действием/результатом и правилом проверки каждой. Упоминание темы в тексте не означает её проверку. Задание считается одним из 30, но может дать по одному наблюдению для каждой действительно проверенной темы; несколько шагов одной темы в одном задании не заменяют два разных вопроса |
| DGN-11 | Приоритизировать темы на основании последних результатов | Основная приоритетная группа: темы с выявленными проблемами в последних диагностиках/ДЗ и темы без оценки при подтверждённом прохождении материала. Источники приоритета, даты и причины сохранены в плане. Отрицательная непроверенная реплика ИИ или ошибка OCR сами по себе не доказывают проблему ученика. Утверждённые временные исключения контроля соблюдаются |
| DGN-12 | Раздельно оценивать темы комбинированного задания | Правильно проверенный шаг темы A не доказывает B/C. Для каждой темы сохраняются верно/ошибка/Unknown с причиной и доказательством. Предметный тест использует это только для выявления проблем/неопределённости. Два правильных ответа не подтверждают тему; в точечной диагностике нужен весь обязательный минимум по EVAL-01–08. Ошибка в одной части не делает все связанные темы ошибочными без основания |
| DGN-13 | Явно показывать недостаточное покрытие | По теме отчёт содержит плановое/фактическое число проверенных заданий и обязательных компонентов, результаты и причины отбора/Unknown. Предметная диагностика никогда не создаёт подтверждение темы, даже при полном успехе своего плана. Точечная не подтверждает при U или неполном обязательном покрытии. Неохваченная тема не считается проваленной; прежние подтверждения/даты сохраняются |

### Формирование набора 27+3, приоритеты и комбинирование

Согласован фиксированный набор: 27 обязательных и 3 необязательных со «*». Прежнее предложение `max(27, 2 × N)` **отменено**. Не увеличивать набор или сокращать число тем молча.

- Сначала сформировать каталог тем текущего учебника/класса и применить утверждённые временные исключения. Не ограничиваться числом «пройденных тем» ради прежнего порога размера теста: он отменён. Из каталога выбрать проверяемую область с явным отчётом о непокрытых темах.
- Приоритет отдать двум названным заказчиком категориям: выявленные проблемы по последним тестированиям/ДЗ; отсутствие оценки при подтверждённом прохождении материала. Между этими категориями заказчик строгий порядок не задавал. Предложение для воспроизводимости: сохранять снимок последних доступных результатов и причины, внутри приоритетной группы учитывать свежесть/повторяемость доказанных проблем и давность проверки; точные веса оформить как версионную настройку, не скрытый вывод ИИ.
- Для каждой выбранной темы стремиться включить минимум 2 разных задания. Допустимо комбинировать связанные темы в одном задании, например уравнения, дроби и раскрытие скобок. Для каждой темы нужен отдельный проверяемый компонент; число тем не увеличивает физическое число вопросов. «2–3 темы» — пример заказчика, а не установленный жёсткий предел.
- Пример: вопросы Q1 и Q2 содержательно проверяют темы A/B/C. Всего это два вопроса, но по два независимых задания для каждой темы. Если в Q2 проверен только компонент A, у B/C остаётся недостаточное фактическое покрытие. Само совпадение итогового числа не доказывает правильность всех компонентов.
- При нехватке мест выбрать темы по приоритету. Предметная попытка 27+3 может завершиться с неполным покрытием каталога; отчёт явно показывает проверенные/непроверенные темы. Она не выдаёт подтверждения даже темам с двумя верными ответами, а выявляет проблемы и рекомендует точечную диагностику. Неохваченные темы не становятся «не освоенными», прежние результаты не удаляются. Несколько предметных попыток за цикл не являются обязательным требованием и не заменяют точечную диагностику.
- Плановое покрытие предметного скрининга может включать «*». Их разрешено пропускать без штрафа, фактическое покрытие отражается в отчёте. В точечной диагностике обязательный базовый минимум должен проверяться обязательной частью: необязательное задание не является единственным доказательством обязательного компонента и не закрывает Unknown автоматически.
- При недостатке текущих тем дополнить набор вопросами по темам прошлого учебного года до 30, сохраняя 27+3 и отсутствие дублей. Для них хранить тему, класс/год и источник; отмечать как повторение, не как тему текущего учебника. Предложение аналитика: добирать прошлогодними темами места, оставшиеся после планирования минимум двух вопросов на выбранную текущую тему. При отсутствии подтверждённого каталога прошлого года нельзя его придумывать: подготовить источник/банк либо показать невозможность сформировать полный план.
- Факт подтверждённого прохождения материала хранится отдельно от оценки: тема, источник/событие подтверждения, автор и дата. Выбор текущей темы, упоминание её ИИ или позиция в оглавлении не создают это подтверждение автоматически. Старым данным без доказательства его не назначать.

Дневной лимит сохраняется: тест можно приостановить и продолжить. Вопросы, попытки ответа, сообщения и вызовы ИИ считаются отдельно. Обязательные/сложные вопросы прошлогодних тем и текущего года различимы в итоговом отчёте; по одной отметке текущей темы не начисляются знания.

### Контрольный пример из обращений 13–14

По переписанным уравнениям все семь конечных ответов верны. Фотография в этом запросе не приложена: соответствие транскрипции исходному изображению не проверялось. Хвост «Переписаны все 7 уравнений…» — комментарий к транскрипции, не восьмое задание.

| Задание | Условие | Ответ ученика | Точный эквивалент / ожидаемый статус |
|---|---|---|---|
| 145а | 5x = −60 | x = −12 | Верно, подстановка −60 = −60 |
| 145б | 6x = −50 | x = −8,(3) | −25/3; верно, период не конечное −8,3 |
| 145в | 0,7x = 0 | x = 0 | Верно; коэффициент 0,7 ≠ 0, деление на него допустимо |
| 146а | (1/3)x = 12 | x = 36 | Верно |
| 146б | −4x = 1/7 | x = −1/28 | Верно |
| 146в | (1/6)y = 1/3 | y = 2 | Верно |
| 146г | (11/7)x = 4 5/7 | x = 3 | Правая часть 33/7; верно |

Приёмочные формы ввода: исходный Markdown с `##`, TeX `\(...\)` и `\frac`, обычный текст из второго примера, ввод через редактор, OCR-транскрипция после подтверждения. Все формы должны сохранять одинаковый математический смысл. Для второго примера достаточно полного результата по 145а–в, без требования сначала объяснить 145а.

Ответ модели из обращения 14 содержит верный результат, но объяснение «любое число на ноль» само по себе не доказывает единственность x=0. Предметный результат должен опираться на ненулевой коэффициент 0,7, а не объявлять весь ответ модели проверенным из-за совпавшего конечного числа.

| MIG-03 | Не пересчитывать прошлое по новым правилам | Старые трёхвопросные диагностики остаются историческими попытками старого формата, а не становятся 10/30-вопросными. Не достраивать ответы, не переоценивать старое освоение, не нормализовать старые тексты и имена в снимках занятий |
| MIG-04 | Мигрировать каталог без автоматической потери связей | Стабильные старые ID сохранены либо есть явное соответствие; неуверенное сопоставление не объединяет темы автоматически. Старые темы видны в архиве, новые без результатов имеют неизвестный уровень. «Пройдено» не выводится автоматически из текущей темы |
| MIG-05 | Сохранить незавершённые занятия | Старую диагностику можно завершить по сохранённому старому плану либо явно архивировать как незавершённую и начать новую; не дописывать вопросы незаметно. Время обновления не начисляется; черновики и ДЗ не теряются |
| MIG-06 | Безопасные значения новых полей | Нет автоматических исключений контроля; новые облачные согласия выключены. Старый verified=False отображается как «нет независимой проверки», без переписывания самого исторического ответа модели. Старым вопросам без ID не придумывать точную историю дедупликации, тематические компоненты или подтверждение прохождения. Старые оценки сохраняются, непопадание темы в новый тест их не отменяет |
| MIG-07 | Атомарность, повтор и возврат | Отказ записи/места/прерывание оставляет рабочую базу или проверенный путь восстановления. Повтор не дублирует темы/планы/запросы. Резервная копия содержит оригиналы и новые метаданные; возврат — к отдельной полной старой копии, без обещания обратного слияния новых данных |

Номер SQL-схемы определить проектированием: новые JSON-поля не требуют автоматического повышения, новые таблицы/ограничения требуют версионной миграции и тестов. Обновление не должно отключать шифрование и атомарное сохранение ради скорости.

### Обязательная матрица приёмки

1. **Диагностика:** тема 8+2, предмет 27+3 при 0/1/2/3/13/14/15/16 и большом числе тем; комбинирование 2–3 тем, отдельные правильные/ошибочные/unknown-компоненты; приоритет последних доказанных проблем и пройденных тем без оценки; переполнение каталога с явным неполным покрытием без ложного подтверждения. Дополнение прошлым годом, отсутствие его каталога, пропуск одного/всех «*» без штрафа и с корректным фактическим покрытием; недоступный ИИ, нехватка банка, повтор ответа, новая попытка, пауза/перезапуск/лимит времени. Нет дублей внутри попытки; повтор между разными попытками допустим. Всегда 30 заданий предмета, независимо от числа тематических компонентов.
2. **Учебники:** исправление опечатки, замена издания, ученический запрос, родительское решение, два родителя с конфликтом revision; нет ИИ/сети, отказ нормализации, ответ после новой ручной правки; исходное имя и история сохранены.
3. **Программы и темы:** точная/одноимённая школа, кандидат с источником, недоступная сеть, не найдено, ссылка родителя и некорректная ссылка, неполное оглавление, смена школы/издания во время поиска; никогда не выдумывать подтверждённый учебник или программу.
4. **Карта:** полный каталог, неизвестные/изученные/архивные темы; запрос отключения, отказ, изменение даты, одновременное решение, наступление даты при закрытой программе, восстановление контроля; история и mastery не обнулены.
5. **ДЗ:** фото печатного текста и рукописного черновика, низкое качество и неоднозначные символы, редактор формул и исправление, отсутствие согласия, ручной fallback, прямая проверка и подсказка отдельно, уточнение в той же работе. Эталонные 7 и 3 уравнения, неверный знак, ошибочная дробь и неподдерживаемая формула: правильное не объявлять неправильным, unknown не считать успехом.
6. **Отображение:** оба дизайна × три темы, Markdown/TeX, ошибочный TeX, большой текст, копирование/вставка, XSS-подобный текст и офлайн-режим. Исторические сообщения тоже читаемы без массовой перезаписи базы.
7. **Миграция:** синтетическая копия последней версии до/после, количество/ID/связи и исторические значения, побайтовая сверка расшифрованных оригиналов, повторный вход и новая запись. Сбой в каждом критичном этапе, повтор и restore; регрессия прежних таймера, меню, приватности и сохранения.

Результат поставки: спецификация решений, список задач с трассировкой к обращениям, проверяемые источники программ/тем, сценарии и протокол на исходниках **и новом Portable exe**, инструкция обновления/возврата. Известные непроверенные сценарии перечисляются явно; положительный текстовый запрос GigaChat не заменяет эти проверки.

## 10. Готовность требований

**Уточнение 28.10.2026 имеет приоритет над прежними формулировками о возможности подтверждения по двум вопросам предметного теста:** приняты разделение скрининга и точечного подтверждения, строгая проверенность и причины Unknown. Формулы, примеры C=2/W=0/U=1, действия, данные и приёмка — в [дополнении](learning-assessment-requirements-2026-10-28.md). Q7 закрыт последующими ответами: 80%, первый самостоятельный ответ, связанный родитель для ручной проверки и обязательное включение ошибочных тем. BANK-1 заменён ответами Q8; открыты три границы реализации из постановки банка.

Все полученные ответы применены к DGN, BOOK, CUR и HW. Конфликт покрытия снят: разрешены содержательно комбинированные задания и неполное покрытие каталога без нового подтверждения непроверенных тем. Согласованы приоритеты последних выявленных проблем и подтверждённо пройденных тем без оценки. Размер предметной диагностики остаётся 27+3; обязательного цикла нескольких тестов нет.

Состав функциональных доработок и Q7 готовы к постановке: 80%, первый самостоятельный ответ, родительская ручная проверка и обязательные ошибочные темы. Ответы Q8 определили полный генерируемый банк с ИИ-проверкой и родительским утверждением; все три уточнения закрыты в learning-bank-requirements-2026-10-28.md: без полного учебника хранятся метаданные/история; при ИИ-only требуется решение родителя; каждая новая подборка утверждается отдельно. При техническом проектировании явно описать обязательную рубрику и компоненты, версионную политику подтверждения и обязательную группу ошибочных тем. Общая формула legacy mastery не заменяется новым процентом автоматически.

Пакет готов к технической декомпозиции с сохранением различий между фактом прохождения материала, покрытием диагностики, результатом проверки и исторической оценкой. Реализация, миграция рабочих данных и публикация в рамках анализа не выполнялись.
