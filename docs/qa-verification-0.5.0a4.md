# Проверка исправления QA-050-06 в 0.5.0a4

Дата: 28.10.2026. Среда: Windows 11 x64, Python 3.13.15, Qt WebEngine. Проверка разработчиком; новый независимый QA после изменения ещё не выполнен. Старые отчёты, реестры и доказательства не изменяются.

## Воспроизведение и граница принятия

До исправления неизменённый независимый `docs/evidence/qa-retest-050a3-2026-10-28/test_additional.py` дал **1 failed**: при clock=100/160/220 last_action оставался 100; при 281 четвёртый запрос отклонялся с time_limit и паузой на 180 секундах.

Исправление в `Learning.work_check()` / `launch()`: сначала штатный checkpoint для прежнего активного занятия; затем атомарно сохраняются связанное занятие, задача, операция и вызов; только после commit обновляются runtime-активность и указатель. Для существующего занятия успешный last_tick не сбрасывается. На фоновом завершении обновления активности нет. Ошибка уже сохранённого запуска не отменяет факт принятия.

| Требования | Проверки |
|---|---|
| ACT-050-01–03 | Четыре запроса 100/160/220/281, отдельно check/hint/follow_up и смешанная последовательность; одно занятие active, 181 с и такой же daily |
| ACT-050-04–06 | +179/+180/+181 от последнего действия; настоящий idle до следующего запроса; snapshot, overview, polling не обновляют last_action; регулярные действия не обходят limit+900 |
| ACT-050-07–08 | Replay/conflict, неверные intent/revision, неподтверждённое решение, контекст 30 000, отсутствие согласия; отказ первого checkpoint и отдельный отказ принятия после успешного checkpoint; первая задача без осиротевшего занятия |
| ACT-050-09–10 | Принятая задача, затем success/network/cancelled/stale/logout; публикация после idle не оживляет занятие и не меняет часы нового контекста |
| QA-050-01–05 | Прежние независимые и целевые тесты, фактические режимы HTTP, предметы/черновики, автопауза при заблокированной записи |

Новый набор `tests/test_qa_053.py`: **24 случая**, плюс исходный независимый тест. Первоначальный целевой прогон до добавления двух проверок прямого запроса после idle: 23 passed. Итоговые результаты полного набора и новых GUI/exe-проверок фиксируются в manifest и JUnit.

Итоговый полный прогон: **291 passed in 225.52s**, без исключений. Ruff и `node --check` прошли.

Полный прогон включает `tests` и все три независимых файла. Используется `--import-mode=importlib`: два независимых файла называются `test_additional.py`, и стандартный импорт pytest вызывает конфликт имён при совместном сборе. Их содержимое и ожидания не менялись; первый остановленный collection-прогон не считается функциональной проверкой.

## Готовый exe и реальные часы

`tests/exe_qa_053.py` / `tests/gui_qa_053.js` используют отдельную Portable-папку, реальные формы и clock Windows, локальный HTTP stub. Три успешных запроса с интервалами 60/60 секунд и наблюдение через 70 секунд проверяют сохранение одного active-занятия и согласованность дневного расхода. Затем без новых действий выполняются наблюдение около 178 секунд после последнего ответа и ожидание настоящего idle. Критерий — `active_dialogue_preserved=true` вместе с проверкой секунд и последующей паузой, а не только завершение скрипта.

**12 условий прошли на готовом a4.** Успехи запросов: 0.316 / 60.571 / 120.805 с от старта. На 190.913 с, через 70.108 с после последнего успеха, одно занятие оставалось active; seconds и daily равны 186.8884185999923 (снимок между периодическими checkpoint). При возрасте последнего ответа 178.026 с — active. При 188.072 с — paused; seconds и daily равны 300.562514499994 и больше не растут. Это реальное ожидание, часы продукта не подменялись.

Прежние бинарные наборы: `exe_qa_051` — QA-050-01–03, 30 условий предметов/черновиков, a1; `exe_qa_052` — 33 условия режимов и 12 фактических HTTP-payload; `exe_fault_052` — реальная временная блокировка замены файла отдельной тестовой базы и повтор автопаузы; `exe_learning_050` — 30 общих условий и обновление 0.4.1. Системные права не меняются, диск не заполняется, рабочие данные не используются.

Все перечисленные бинарные наборы прошли на одном SHA256 a4. Fault: 11 условий, файл неизменен при блокировке; после её снятия начислено ровно 180 с без дублей. Grace-fault отдельно на exe не вводился, он покрыт нативными тестами. Обновление 0.4.1: 5 UI + 10 нативных условий; a1: 8 UI; a1/a2/a3: по 13 нативных условий. Все источники сохранены. `--smoke` без DevTools из `C:\Windows`: exit 0, снимок получен, данные рядом с exe.
