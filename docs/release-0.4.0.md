# Tutor-AI 0.4.0 — переименование и сохранение данных

Прежнее английское имя AI-Tutor/AITutor заменено на **Tutor-AI**. Русское название «ИИ-репетитор» сохранено. Python-пакет — `tutor_ai`, дистрибутив — `tutor-ai`, Windows Portable — `Tutor-AI-0.4.0.exe`.

Формат vault, SQL-схема **3**, имена `app-data/data/vault.aead`, расширение `.aitbackup` и криптографические идентификаторы совместимости сохранены. Исторические названия внутри профилей, сообщений, заданий и оригиналов не заменяются. Миграции схем 1/2 → 3 выполняются после проверки прежнего пароля со снимком зашифрованной базы перед изменением. Существующим ученикам сохраняются правила назначения дизайна «Современная».

## Два способа перехода

1. **Новый exe рядом с данными.** Закройте прежнее приложение. Скопируйте всю старую установку в отдельную папку для возврата. Поместите новый exe рядом с прежним `app-data/`, запустите и войдите в существующий профиль. Не создавайте вложенный `app-data/app-data`. Старая копия exe без отдельной копии данных не обеспечивает возврат.
2. **Встроенный перенос.** Запустите новую пустую установку. До регистрации нажмите «Перенести данные из прежней версии → Выбрать папки». Выберите корень старой установки, проверьте показанные пути, укажите прежний профиль и пароль. Можно выбрать другую **пустую** папку: из Portable exe в неё копируются новый exe и данные. После успеха доступен запуск новой установки. При запуске исходников используется только текущий каталог проекта; для создания отдельного комплекта нужен Portable exe.

Источник блокируется совместимым `instance.lock` и не изменяется. Проверяются свободное место, пути, отсутствие ссылок/junction, список, размеры и SHA256 файлов. Неизвестные постоянные файлы сохраняются; кэш, lock и `.pending` не копируются. Исходно отсутствующий оригинал ДЗ блокирует полный перенос с отдельным сообщением.

Авторизация, проверка SQLite/ссылок, расшифровка оригиналов и прежние миграции выполняются во временной целевой копии. Никакие сетевые проверки провайдеров не выполняются. Новые ID и семья не создаются. Незавершённые занятия приостанавливаются без начисления времени переноса. Пароль проверочной сессии не сохраняется; после переноса нужен новый вход.

## Прерывание и возврат

Назначение с постоянными данными отклоняется без слияния или перезаписи. Во время публикации журнал блокирует обычные регистрацию и вход. При ошибке устраните причину и нажмите «Очистить незавершённую копию после ошибки». После перезапуска можно выбрать «Очистить незавершённый перенос в другой папке». Полностью опубликованная копия проверяется и завершается; неполная удаляется только при совпадении данных операции. Изменённые извне файлы автоматически не удаляются. Исходная установка остаётся доступной.

Для возврата используйте сохранённую старую папку. Созданные только в новой версии данные автоматически обратно не переносятся; объединения и понижения схемы нет. Ручные старые `.aitbackup` используют прежний пароль архива и родительские данные из копии; автокопия требует ключ своего vault.

## Надёжность записи

Проверка переноса обнаружила, что SQLite после `deserialize()` может сериализовать прежний образ до фиксации изменённых страниц. Теперь приватная база в памяти сначала фиксируется, затем атомарно публикуется её новый зашифрованный образ. При отказе записи восстанавливаются предыдущий образ в памяти и заголовок ключевых обёрток. Регрессия проверяет немедленное повторное открытие после каждого изменения и сохранность памяти/файла при отказе.

Результаты и ограничения выпуска фиксируются в [протоколе 0.4.0](qa-verification-0.4.0.md). Исторические протоколы и сборки не заменяются.
